# Finish review of the styled UI

The finish review on the real build, as `review-comps.md` promised: the
styled Svelte layer (`apps/quest-tracker/src/`, `apps/quest-tracker/theme/`)
in the browser preview, every frame id of the brief in play and edit mode at
1x and 2x (52 screenshots, `<frame>--<mode>--<scale>x.png`), and one capture
of the real Tauri window over the desktop (`real-window.png`, from `npm start`
at 2560x1440, waiting-for-the-game state). Compared against
`docs/quest-tracker/design/frames/` and `component-spec.md`. Tools:
impeccable 4.7.1 (detector, critique, audit) and taste-skill 2.1.5
(app-screen rules: `lint.mjs --app`, `inspect.mjs --app`). Report only; no
fix was applied.

detector: ran. Over the source (`.svelte`, `.css`, `.ts`, 31 files, regex rules) it found nothing; over the running preview (every frame, both modes, 1x) it reported low-contrast, tight-leading and straggler. Real: muted header text on the edit tint, 4.3:1 (F5). False positives: every "#959084 on #5c636d / #3ccfcf" and the Reset button's "#f28b82 on #f28b82" read the `.cut::after` border ring as the background (real ground #121416, 5.8:1); tight-leading on empty-state body text is the spec's Step style (14/18); the straggler is a wrapped log path.
critique: Nielsen 29/40, "Good". The build matches the comps' shape system, palette, type scale, status shapes, edit chrome and toast placement at 1x and 2x. Lost points: the rows' long game reward text crowds out quest names (F1), the act header lacks its available count (F2), the detail's second tick box makes done steps look unticked (F3), and status lines repeat the empty state (F7).
audit: Focus-visible rings on every control, reduced-motion handled, all controls named, nothing under 12 px. Blocking: Auto scale gives 1x at 1440p on a 100% DPI monitor (F4, seen in the real window), and one AA contrast failure (F5). Polish: 16-20 px hit targets (F3, F14), no heading or live-region semantics (F13), and a hover outline at 1.7:1 (F11).
taste: passes the app-screen rules once each flag is triaged. Lint gave 10 FAIL and 17 WARN, none a real tell: the gradient is the slider's hard-stop fill; the "emoji" are `theme.ts` fallback glyphs, drawn only when an SVG is missing; `example.com` is in a test; the shadows are inset focus and hover rings plus the floating panel's drop shadow; "unlock" is a reward category id. `inspect.mjs --app`: no-title (F13); palette-cream is the owner's bone ink #ECE6D9; hero-void is the transparent window around a 320 px overlay. Violet for unknown and teal edit chrome are owner decisions.

findings:

Known gaps that are documented, not findings (`docs/quest-tracker/README.md`
§ "Parts of the comps the view does not carry yet"): one hotkey
(`Ctrl+Alt+Q`) where the comps show F8/F7/F6/F1; "Open settings" in place of
Browse…/Retry and the "Looked in" path; no "New character" button; no
hidden-quests footer; no log-idle header. Still open from the comps review:
arrow-key navigation through rows (rows take Tab and Enter, not ↑/↓).

- **F1** — class: the reward text on every quest row (both views, both modes) is the full game string ("+10% to Cold Resistance"), not the short label the owner chose ("Spirit", "Passive · Cold res"). The 132 px reward column then cuts most quest names to a few words. Files: `apps/quest-tracker/src/components/QuestRow.svelte:15` (`rewardText`), `apps/quest-tracker/src/labels.ts`. Fix: add a short label per reward category or icon in `labels.ts` (spirit → "Spirit", passive_points → "Passive", res-cold → "Cold res", life → "Life", …). Join those in the row and keep the full text in the row's `title` and in the detail's reward chips. Severity: blocking (contradicts the comps and the brief).
- **F2** — class: every act header shows the available icon with no count; the comps show "4 available · 1/9 done". Files: `apps/quest-tracker/src/components/ActSection.svelte:16-19`. Fix: count the act's rows whose status is `available` and render "{n} available ·" after the icon when n > 0 (or carry the count in `ActView`). Severity: blocking (contradicts the comps).
- **F3** — class: in edit mode, every step row in quest detail has a second, trailing hand-tick box beside the leading state mark. A step the log already finished shows a check and an empty box, which reads as "not done". The box is a 16x16 target, and the comps show one leading mark only. Files: `apps/quest-tracker/src/components/QuestDetail.svelte:97-111` and its `.tick` styles (~330-350). Fix: make the leading step mark the toggle in edit mode (a button around the mark, at least 24x24), drawn as the check-in-box when done or hand-ticked, and drop the trailing box. If the trailing control stays, hide it on log-done steps and draw "ticked" with the same check-in-box glyph. Severity: blocking (confusing state; contradicts the comps).
- **F4** — class: the "Auto" scale always resolves to 1x and relies on Windows DPI. On a 2560x1440 monitor at 100% DPI the real window renders at its 1080p size (`real-window.png`), so captions are 12 px on a 1440p screen; the brief says 1.33x at 1440p and 2x at 4K. Files: `apps/quest-tracker/crates/qt-app/src/app.rs:109-116` (`scale_factor`). Fix: for Auto, choose by the monitor's physical height (≥2160 → 2, ≥1440 → 1.33, else 1), divided by the monitor's DPI scale factor so a 150% DPI 4K screen is not doubled twice. Severity: blocking (wrong size on the target displays).
- **F5** — class: the "Quest tracker" placeholder name (no character yet) in `color.text-muted` on the edit-mode header tint is 4.3:1, below AA for 16 px text, in every empty frame in edit mode. Files: `apps/quest-tracker/src/components/Header.svelte:95-97` (`.name.none`). Fix: use `color.text-secondary` (6.8:1 on the tint), at least in edit mode. Severity: blocking (inaccessible contrast).
- **F6** — class: adjacent in-progress rows merge into one band with one unbroken blue bar, so two quests read as one block (next-up and toast frames). Files: `apps/quest-tracker/src/components/QuestRow.svelte:136-152`. Fix: inset the bar vertically (`top: 4px; bottom: 4px`), or add a 1px `color.panel-divider` top border on an in-progress row that follows another. Severity: polish.
- **F7** — class: the header status line repeats the empty or error state shown under it ("No Client.txt found…" over "Can't find Client.txt"; "Waiting for the game to write to the log." over "Waiting for the game", also in the real window). Files: `apps/quest-tracker/src/components/Panel.svelte:41-46`. Fix: suppress the status line when the body is an empty state for the same condition, and keep it for problems the body does not show. Severity: polish.
- **F8** — class: every keycap in an inline hint ("Press [Ctrl+Alt+Q] …", every empty state in play mode) sits below the text baseline and is taller than its line. Files: `apps/quest-tracker/src/styled.css:182-192` (`.keycap`). Fix: `vertical-align: middle` (or a 1 px raise), `line-height: 14px`, and the spec's 1/6 padding. Severity: polish.
- **F9** — class: Settings helper copy and field spacing. The click-through helper "On returns to play mode: the panel passes clicks to the game." reads garbled (the spec has "Off: the panel blocks clicks to the game."). "Empty: found automatically." touches the log-path field. A long path is clipped mid-word with no ellipsis. Files: `apps/quest-tracker/src/components/Settings.svelte:54`, `:112-119`, `.help` at ~186. Fix: rewrite as "On: in play mode the panel passes clicks to the game."; add a 4 px top margin to `.help` after a field; ellipsize the path (or show its tail) with the full path in `title`. Severity: polish.
- **F10** — class: the character picker's active-row accent bar sits at `left: 0`, under the 2 px edit border, so it never shows. Files: `apps/quest-tracker/src/components/CharacterPicker.svelte:104-112`. Fix: `left: 3px`, as the in-progress bar already does. Severity: polish.
- **F11** — class: the edit-mode hover outline on every row (`color.hover-outline` #3A4048) is about 1.7:1 against the panel and the active band, so hover is barely visible. Files: `apps/quest-tracker/theme/theme.json:46`, `apps/quest-tracker/theme/tokens.css:88`. Fix: raise it to about `color.panel-border` (#5C636D) for at least 3:1 non-text contrast. Severity: polish.
- **F12** — class: the preview fixtures disagree across frames and miss variants. Every quest is worth "yes", so the optional star and the not-worth dash never render. One act counts 5 total over 6 rows. The character's level differs between the header and the picker. One quest is skipped in one frame and in progress in another. Files: `apps/quest-tracker/fixtures/viewmodels/*.json`. Fix: one consistent fixture set with each worth and detection variant, and counts computed from the rows (the comps' round-3 rule). Severity: polish.
- **F13** — class: no heading or live-region semantics. The panel has no `h1`; the frame titles (Settings, Characters, the quest name in detail) are not headings; the header status line is not announced. Files: `apps/quest-tracker/src/components/Header.svelte`, `QuestDetail.svelte`, `Settings.svelte`, `CharacterPicker.svelte`, `Panel.svelte:43`. Fix: the panel name in an `h1` (visually unchanged), frame titles as `h2`, and `role="status"` on `.status-line`. Severity: polish.
- **F14** — class: the edit-header controls (character picker button, Next up / All switch) are 20 px tall, under the 24 px target minimum. Files: `apps/quest-tracker/src/components/Header.svelte` (`.who`, `.switch button`). Fix: `min-height: 24px` with the visual size kept through padding. Severity: polish.
